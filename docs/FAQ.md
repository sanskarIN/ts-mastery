# Frequently Asked Questions

## Is this repository the complete eBook?

No. It is the public companion-code repository. The complete commercial eBook is available from **https://ramsandesh.gumroad.com**.

## Why are there 120 part folders but fewer/more runnable projects?

Part folders are curriculum navigation anchors. A reusable project can support several parts, and a part can link to more than one project.

## Do I install dependencies inside every project?

No. Install once at the repository root with `npm install`.

## What is the main verification command?

```bash
npm run verify
```

It checks structure, docs, strict TypeScript, a clean build, and all tests.

## Can I run only one project test?

Yes after building, for example:

```bash
npm run build
node --test dist/projects/typed-store/src/typed-store.test.js
```

Still run the complete verification before contributing.

## Why are imports written with `.js` in `.ts` files?

The repository uses ESM with TypeScript `NodeNext`. The `.js` specifier produces Node-compatible emitted imports while TypeScript resolves the source module during compilation.

## Why are many projects dependency-free?

The repository is designed to teach the TypeScript/architecture concept directly and avoid a large, quickly changing dependency tree.

## Are these production-ready libraries?

They are tested educational implementations. Some model production patterns, but production adoption requires additional domain, persistence, observability, security, concurrency, and performance analysis.

## Where is `dist/`?

It is generated by `npm run build` and intentionally ignored by Git.

## Which Node.js versions should I use?

Node.js 20 or 22. See [Compatibility](COMPATIBILITY.md).
