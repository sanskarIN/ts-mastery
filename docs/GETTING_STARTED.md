# Getting Started

This guide gets a fresh clone of the TypeScript Full Mastery companion repository into a verified development state.

## Prerequisites

Use Node.js **20 or 22** and npm. The repository is ESM-first, targets ES2022, and is compiled with TypeScript in strict mode. Git is recommended for normal contribution workflows.

Check your tools:

```bash
node --version
npm --version
git --version
```

## Clone and install

```bash
git clone https://github.com/sanskarIN/ts-mastery.git
cd ts-mastery
npm install
```

The repository intentionally keeps runtime dependencies minimal. Most learning projects use TypeScript and Node.js built-ins only.

## Verify everything

Run:

```bash
npm run verify
```

A successful verification means:

- all 120 curriculum folders are present exactly once;
- every runnable project/example has the required source, test, and README structure;
- every runnable group is represented in `docs/code-catalog.json`;
- local Markdown links resolve;
- strict TypeScript type checking passes;
- a clean compilation succeeds;
- every compiled test file is discovered and executed.

See [Quality Gates](QUALITY_GATES.md) for the exact contract.

## Find the right code

There are three main learning entry points:

1. `examples/` contains small focused examples.
2. `projects/` contains larger reusable companion projects.
3. `parts/` contains the 120-part curriculum navigation layer.

Use [Project Matrix](PROJECT_MATRIX.md) when you know the concept you are studying, or [Parts Index](PARTS_INDEX.md) when you know the book part.

## Edit a project

A typical project looks like:

```text
projects/example-name/
├── README.md
└── src/
    ├── example-name.ts
    └── example-name.test.ts
```

Edit the source and tests, then run:

```bash
npm run verify
```

Do not edit generated files under `dist/`. They are deleted and regenerated by the build.

## Run generated JavaScript

After:

```bash
npm run build
```

compiled files appear under `dist/` while preserving the repository-relative path. For example:

```text
projects/typed-store/src/typed-store.ts
```

becomes:

```text
dist/projects/typed-store/src/typed-store.js
```

The repository is primarily a tested source-code companion rather than a collection of separately published npm packages, so most projects do not provide independent package manifests or command-line entry points.

## Windows notes

PowerShell, Command Prompt, Git Bash, and VS Code terminals can all run the npm scripts. Prefer the npm scripts over manually invoking generated paths because the scripts keep cleaning, compilation, and test discovery consistent across operating systems.
